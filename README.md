# Вебсервіс для скорочення URL

Навчальний монолітний застосунок на Python/Django (ЛР №4 з дисципліни «Життєвий цикл розробки програмного забезпечення»). Архітектура відповідає ЛР №2: Django Auth, модель `ShortLink`, сервіси для створення та перенаправлення, серверні HTML-шаблони та SQLite. Публічного API немає.

## Встановлення і запуск

Потрібен Python 3.10+ та доступ до PyPI для встановлення Django.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver
```

Відкрийте http://127.0.0.1:8000/register/. Для доступу до `/admin/` створіть адміністратора командою `.venv/bin/python manage.py createsuperuser`.

Перевірка: `.venv/bin/python manage.py test` і `.venv/bin/python manage.py check`.

Для розгортання задайте `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS` (список через кому), `DJANGO_DB_PATH` (шлях на постійному диску); налаштуйте HTTPS на довіреному проксі. Локальний сервер `runserver` не призначений для production. Швидкодія за 20 одночасних користувачів і сумісність із браузерами поки що не вимірювалися.

## Структура

- `config/` — налаштування та маршрути Django;
- `links/models.py` і `links/migrations/` — модель та схема SQLite;
- `links/forms.py` — форма перевірки URL і реєстрації;
- `links/services.py` — генерація коду, операції власника, підрахунок переходів;
- `links/views.py`, `links/admin.py` — HTTP-обробники та адмінпанель;
- `templates/links/` — HTML-сторінки;
- `links/tests/` — автоматизовані перевірки;
- `docs/` — архітектура, відповідність вимогам та порядок роботи з Git;
- `.gitignore` — виключення локальної БД, віртуального оточення та секретів.

## Ролі та внесок

Проєкт виконує **Вовк А. А.** індивідуально (як у ЛР №2 і №3). У ролі розробника — модель, сервіси, форми, маршрути й шаблони; у ролі QA — автоматизовані тести; у ролі DevOps — каркас, залежності, Git та документація. Інших учасників і проведеного командного код-рев’ю немає. Для майбутньої командної роботи порядок гілок і перегляду змін описано у `docs/architecture.md`.
